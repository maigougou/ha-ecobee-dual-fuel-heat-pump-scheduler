# 仪表盘卡片

[English](dashboard.md)

卡片显示冷暖状态、热源日程、运行级数、功率和历史报告。通过 [HACS 安装](../README.zh-CN.md#安装与配置)后，在仪表盘选择 **添加卡片 → ecobee Dual-Fuel Heat Pump**。

## 设置

在「编辑仪表盘 → 编辑卡片」中选择：

| 设置 | 用途 |
| --- | --- |
| ecobee 温控器 | 必选，使用 HA 原生 ecobee 集成的实体 |
| Auxiliary heat only 开关 | 同一温控器的辅助供暖开关，用于区分热源模式 |
| 热源调度自动化 | 显示日程、启停开关和设置入口 |
| Managed Auto 控制器 | 可选，用于自动冷暖的状态显示与控制 |
| 热泵功率 | 可选，室外热泵电路的 W/kW 传感器 |
| 炉子／送风机功率 | 可选，室内炉子电路的 W/kW 传感器 |
| 语言 | 默认跟随当前 HA 用户，也可指定英文或中文 |
| 历史报告 | 可整体关闭，也可分别隐藏制暖、制冷或电量 |

功率来源在卡片中设置。「时段与设置」打开 Blueprint 自动化，用于调整热源时段和控制参数。温度、舒适设置和房间传感器仍在 ecobee 中设置。

任意品牌的 W/kW 功率传感器均可使用，两项可独立留空。未选择时隐藏对应功率，已选择但离线时显示不可用；不要选择累计 kWh 电量实体。

## 不同模式的显示

| 模式 | 卡片显示 |
| --- | --- |
| Heat | 热源日程、当前热源、热泵与炉子运行级数 |
| Cool | 制冷目标、热泵制冷、送风机和可选功率 |
| 原生 Heat/Cool | 冷暖双目标及实际运行状态，热源调度暂停 |
| Managed Auto | 冷暖双目标、当前选择的热源、ecobee 实际模式及控制器状态 |
| Off | 温度、停机状态和历史报告 |
| 不可用 | 显示未知，不根据功率猜测设备运行 |

Managed Auto 在热泵时段使用原生 Auto；其他时段根据温度目标切换炉子制暖或热泵制冷。它依赖 HA 和云端，详见[控制器说明（英文）](managed-auto.md)。

## 运行报告

按最近七次连续日程时段统计，跨午夜不拆行。例如 23:00–次日 07:00 属于同一时段。每种设备显示总时间、Stage 1 和 Stage 2。报告跟随温控器模式：Heat 只显示制暖（标题「制暖报告」），Cool 只显示制冷（「制冷报告」）；Heat/Cool（原生或 Managed Auto）、Off 和未知状态以标签页同时提供制暖和制冷，标题为中性的「运行报告」。手动选择的标签在实时更新中保持不变。

报告默认沿用热源自动化的时段，也可在卡片中单独指定分析时段。分析设置不会控制设备。历史按当前日程分组，不保存过去的日程配置。

- 星号表示历史不完整；横线表示没有可用记录。
- 电量由所选功率传感器的历史估算，没有功率监控则隐藏。
- 「仅室外热泵电路」只排除热泵运行期间的室内送风机电耗；炉子制暖仍统计已配置的炉子电路。
- 「热泵与室内送风机」同时统计热泵运行期间已配置的两路电耗。
- 仅送风电量在时段详情中单列。炉子电耗不代表燃气消耗。

高级设置提供积分方式和最大历史间隔。默认使用梯形积分，超过 15 分钟的记录间隔不纳入估算；应按传感器实际采样方式调整。

## 状态含义

热源模式表示允许使用的设备，不代表设备正在运行。运行级数取自 ecobee 的设备报告，不由功率推算。

炉子制暖和送风机状态分别显示。炉子正在制暖但 ecobee 没有报告 Fan 时，卡片显示「由炉子控制」。空设备报告表示待机；缺失数据表示未知。

卡片语言跟随 HA 用户；Blueprint 使用安装时选择的语言。自定义卡片标题、自动化名称和自定义舒适设置名称保留原文。

不使用自定义 JavaScript 卡片时，可选择[原生 YAML 备用卡片](native_dashboard.zh-CN.md)。
